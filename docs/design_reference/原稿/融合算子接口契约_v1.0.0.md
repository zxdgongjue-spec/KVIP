# 融合算子接口契约

> - 版本：`1.0.0`（`DSA_CONTRACT_VERSION = "1.0.0"`）
> - 适用范围：Ascend 950（A5）/ CANN 9.1 + torch_npu；vLLM-DSA decode sparse 卸载路径。
> - 权威性：本文是 `nanovllm_dsa` 融合算子的**唯一权威接口契约**。C++ schema、Python wrapper（`ops_nanovllm`）、stub 与实现均以本文为一致基准；任何不一致应视为缺陷并修正。
> - 配套方案：[重构分析及实现方案.md](重构分析及实现方案.md)。

---

## 1. 契约目标与分层

契约把融合算子划分为三层，隔离"算子提供方（独立仓）"与"框架消费者（vllm-DSA 引擎）"：

| 层 | 内容 | 消费者→提供者 依赖方向 |
| --- | --- | --- |
| L1 常量契约 | ABI 常量（容量、对齐、预算、尺寸） | 引擎与独立仓共享 |
| L2 数据面算子契约 | Python wrapper 函数签名 + 内存/语义规则 | 引擎只调用该层 |
| L3 内核/注册契约 | C++ 算子 schema、别名、启动、OPP 环境 | 由独立仓内部实现，引擎不直接触碰 |

本文 L1、L2 为强契约（必须遵循）；L3 为独立仓内部实现约束，但注册的 schema 与别名是引擎可观察的隐式依赖，故一并记录。

## 2. 通用记号与约定

### 2.1 记号

| 记号 | 含义 |
| --- | --- |
| `B` | 本批请求行数（decode 请求顺序，非稳定身份） |
| `T` | packed query 行数，`T = Σ_b q_b`；ordinary 每请求 `q_b=1`，MTP prepare `q_b∈[2,4]` |
| `P`、`p` | pool 总行数、请求的 pool 行；`p = req_pool_entries[b]` |
| `S_b`（= `cache_tokens[b]`） | 请求 resident cache 容量（可淘汰区，不含 tail） |
| `C_b`（= `candidate_lens[b]`） | 参与稀疏选择的 prefill 满块候选终点 |
| `L_b`（= `logical_seq_lengths[b]`） | 含 resident tail 的逻辑长度 |
| `SPARSE_COUNT` | 固定 2048（`DSA_SFA_COMPUTE_TOPK`） |
| `t`、`s` | 逻辑 token 位置、resident 逻辑 slot |
| source token | 18-bit 逻辑 token 编号；`SOURCE_CAPACITY ≤ 262144` |
| destination slot | 14-bit resident slot；block-aligned `S ≤ 16256`（`DSA_LIDU_MAX_RESIDENT_SLOTS`） |

### 2.2 通用约束

- 数据面热路径 tensor **必须连续**且已在设备（NPU）；wrapper 只做零拷贝 view，不隐式 `contiguous()`/复制大张量。
- `_out` 变体：输出缓冲由 **caller 预分配并持有**（graph-stable），算子原地写回；别名返回 caller 缓冲。
- **从不把设备 miss 计数经 `.item()` 转回 Python**（无 CPU-NPU 同步）；CPU contract 测试的计数上界校验不视为 NPU 上的既有检查。
- 除显式标注 "capture dummy" 外，不执行忽略正确性的分支。
- stream/event 依赖：**函数返回 ≠ payload 到位**。尤其在 KVAF BatchGet → QSFA 之间，调用方必须建立跨 rank 完成依赖；wrapper 不替调用方 `synchronize()`（唯一例外：见 §C8 LIDU 的 `capturing=False`）。

### 2.3 输出布局约定（LIDU 共同语义）

`cache_slots_pool[req_pool_entries[b], token_id]` 保存 source token → HBM slot 映射；`-1` 表示未缓存。

LIDU 输出 `source_ids`/`destination_slots` 的排列保持 **miss-first**：
- 前 `miss_counts[b]` 项为 **miss**（SCATTER 只搬运这段）；
- 全部 `SPARSE_COUNT` 个 `destination_slots` 都供 Attention 使用（hit 也在其中）。

`C=0` 时该请求 LIDU no-op，SFA 计算全部有效 KV。

## 4. L2 数据面算子契约

> 每个条目给出：函数签名、输入/输出表（名称、形状、dtype、语义、in/out 别名）、约束、返回、stream/event 说明。
> 所有 wrapper 以 **keyword-only** 参数接收；形状中的具体维（如 `SPARSE_COUNT`）由 L1 常量决定。

### 4.1 启动与校验

**`require_nanovllm_dsa_ops(*, require_mtp: bool = False) -> None`**

- 加载并校验 `torch.ops.nanovllm_dsa` 命名空间下必需算子已注册；`require_mtp=True` 时额外要求 MTP 变体。
- 校验引擎开关 `enable_sparse_sfa_c8` 与 `enable_sparse_li_c8` 一致性（同开同关）。
- 校验所装独立仓契约版本在 vllm-DSA 支持区间（L1 版本校验）。
- 校验失败抛 `RuntimeError`（不静默降级）。

### 4.5 Fused LIDU Prepare（ordinary，C8）

**`fused_lidu_batch_get_prepare_c8(*, topk_indices, req_pool_entries, token_to_slot_pool, slot_to_token_pool, eviction_cursors, cache_tokens, candidate_lens, miss_slots, miss_slot_bitmap, resident_block_table, logical_seq_lengths, profile_enabled, destination_slots, miss_counts, indices, offsets, output_indices, resident_seq_lengths, profiling, layer_id, num_layers, max_num_reqs, qcap) -> None`**

| 参数 | 形状 | dtype | 语义 |
| --- | --- | --- | --- |
| `topk_indices` | `[T,1,2048]` | i32 | LI 选择（T=B） |
| `req_pool_entries` | `[B]` | i32 | |
| `token_to_slot_pool` | `[P,C_cap]` | i32 | 正向表（in/out） |
| `slot_to_token_pool` | `[P,S_cap]` | i32 | 反向表（in/out） |
| `eviction_cursors` | `[P]` | i32 | 淘汰 cursor（in/out） |
| `cache_tokens` | `[B]` | i32 | S |
| `candidate_lens` | `[B]` | i32 | C |
| `logical_seq_lengths` | `[B]` | i32 | L |
| `miss_slots` | `[B,2048]` | i32 | 有序 victim |
| `miss_slot_bitmap` | `[B,512]` | i32 | victim membership（16384 bit） |
| `resident_block_table` | `[B, rbc]` | i32 | slot→物理块 |
| `profile_enabled` | `[1]` | i32 | 0 关 / 1 记 / 2 graph dummy |
| `destination_slots` | `[B,1,2048]` | i32 | `d!` caller-owned |
| `miss_counts` | `[B+1]` | i32 | `e!`；末项=成功请求 miss 合计 |
| `indices/offsets/output_indices` | 各 `[B*2048]` | i32 | `f!/g!/h!` 全局紧凑 descriptor 前缀，有效域 `[0,miss_counts[B])` |
| `resident_seq_lengths` | `[B]` | i32 | `i!`；成功 sparse 行 = `S+L-C` |
| `profiling` | `[B,8,32]` | i64 | `j!` profile 输出 |
| `layer_id/num_layers/max_num_reqs/qcap` | 标量 | int | 远端目录几何 |

**语义要点**：
- 命中 = `0 ≤ token_to_slot[p,t] < S_b` 且该 slot 不在 victim bitmap。
- 保持 **miss-first** 布局；`indices/offsets/output_indices` 是**全局**紧凑前缀，非每行固定步长。
- 先清旧正向再装新正反；清理前验证旧正向仍指向该 slot。
- ordinary 不推进 `eviction_cursors`，仅用 `miss_slots[:M]`。
- 输出地址与映射地址不得互相覆盖。

底层：`nanovllm_dsa.lidu_fused_batch_get_prepare_out`。

### 4.6 Fused LIDU Prepare（MTP，C8）

**`fused_lidu_batch_get_prepare_mtp_c8(...)`** 签名同 §4.5，另加输入 `actual_seq_lengths_query [B] i32`（累计）。

差异：
- `destination_slots` 为 `[T,1,2048]`；`indices/offsets/output_indices` 为 `[B*8192]`。
- `miss_counts` 为**跨 query unique miss 数**；末项合计。
- MTP 的 unique miss 源列表由**原子操作生成，顺序不稳定** → token→slot 排列**不是**跨实现的逐位 ABI。
- 仅当容量/槽位校验成功后才推进 cursor、发布 descriptor；失败则该请求 destination 全 `-1`、miss `-1`、resident length 0。错误码 `-106/-107/-109` 是 MTP 专属 profile 错误。

底层：`nanovllm_dsa.lidu_fused_batch_get_prepare_mtp_out`。

### 4.11 Capturing / 时序配置接口

为消除对 `vllm.forward_context` 的强依赖，契约提供显式的时序配置注入点（**引擎负责**从 vLLM 上下文取值后传入）：

```python
# 独立仓契约提供（stub 与真实现同签名）
class DSATimingContext(NamedTuple):
    capturing: bool = False   # 是否处于 ACL Graph capture
    synchronize_non_captured: bool = True  # 非捕获时是否同步（仅 C8 LIDU 涉及）

def set_timing_context(ctx: DSATimingContext) -> None: ...
def get_timing_context() -> DSATimingContext: ...
```

引擎（vllm-DSA）在每次前向开始时设置 `capturing = bool(get_forward_context().capturing)`。这样独立仓不再 import `vllm.forward_context`。

### 4.12 辅助数据面函数

- **`build_c8_attention_metadata(*, destination_slots, cache_tokens, candidate_lens, actual_seq_lengths_kv, max_tail_tokens, resident_seq_lengths, attention_slots) -> resident_seq_lengths`**：只写 `attention_slots`，不搬 KV、不发 URMA、不读写 packed payload。`attention_slots` 跨层跨步复用，每轮完整覆写（等价旧 ClearAttentionRow + 写值）。`resident_seq_lengths` 为只读（唯一 writer 是子图 C resolver）。
- **`packed_full_kv_cache_blocks(*, hbm_packed_kv, dram_packed_kv, src_block_ids, dst_block_ids) -> None`**：final-Prefill 满块 HBM→swap DRAM dump。落后：`nanovllm_dsa.packed_full_block_dump`。`dst_block_id == -1`（`DSA_DUMP_NOOP_DST_BLOCK_ID`）解释为 no-op；有效物理 DRAM block id 从 1 起（0 为空映射）。
- **BF16 full_block_dump**：`nanovllm_dsa.full_block_dump`（适用于 `ops.py` 的 `dump_full_kv_cache_blocks` 首选路径；回退 `_C_ascend.kv_cache_full_block_dump` → torch fallback）。
- **`mtp_graph_padding_abi_available() -> bool`**：标识 A5 OPP 是否支持 padded MTP graph tail 行（读取独立仓安装目录的 `.dsa_mtp_graph_padding_abi` 标记，版本 ≥1）。防止源更新喂旧 kernel 或反向。

## 5. 返回与错误契约

| 类别 | 约定 |
| --- | --- |
| 返回 | wrapper 返回 L2 表标注的 tensor 或 `(…_alias)` 三元组；`_out` 变体返回 caller 缓冲别名。 |
| 失败 | 校验失败抛 `ValueError`（非法形状/dtype）；算子不可用/版本不符抛 `RuntimeError`；MTP 容量/槽位失败**不抛**，而是将 destination 全 `-1`、miss `-1`、resident length 0（见 §4.6）。 |
| 错误码 | `-106/-107/-109` 仅 MTP prepare 路径，不应误读为 ordinary 的通用错误。 |
| 同步 | 除 C8 LIDU 在 `capturing=False` 且 `synchronize_non_captured=True` 时执行 `torch.npu.synchronize()` 外，wrapper 不做设备同步；stream/event 依赖由上层建立。 |

## 6. L3 内核/注册契约（独立仓内部约束）

### 6.1 Torch schema 与别名（引擎可观察）

| 算子 | schema 别名 |
| --- | --- |
| `lidu_decode_update_out` | `(Tensor(a!) cache_slots, Tensor(b!) source_ids, Tensor(c!) destination_slots, Tensor(d!) miss_counts)` |
| `scatter_copy` | `(Tensor(a!) hbm_kpe, Tensor(b!) hbm_ckv)` |
| `packed_scatter_copy(_out)` | `(Tensor(a!) hbm_kv, Tensor(b!) attention_slots, Tensor(c!) resident_seq_lengths)` `_out` 同 |
| `fused_batch_get_prepare(_out)` / `_mtp(_out)` | `(a!..j!)` caller-owned in/out（见 §4.5/4.6） |
| `full_block_dump` / `packed_full_block_dump` | `(dram_kv a!)` / `(dram_packed_kv a!)` |
| `lidu_cache_update(_out)` | `(Tensor(a!) cache_slots_pool)` |

### 6.2 OPP 环境契约

独立仓 `__init__.py` 负责设置 `ASCEND_CUSTOM_OPP_PATH`、`NANOVLLM_CUST_OPAPI_LIB`、`NANOVLLM_A5_INSTALL_OPP_PATH`；vllm-DSA 只调用 `local_opapi_path()` 契约入口，不自行拼路径。ACLNN 启动经 `nanovllm_a5_vllm_op_api_bridge.h` 解析 `libcust_opapi.so`/`libopapi.so`，并 honor 实时 `ASCEND_CUSTOM_OPP_PATH`。

### 6.3 数据布局约束（内核）

- BF16: Indexer head 32|64、QK head dim 128；KV LoRA 512 + RoPE 64。
- C8：packed KV 656B/token（512 FP8 + 64 BF16 RoPE + 4 FP32 scales）；整行搬运；indexer 独立 FP8 key + FP32 scale cache。
- block size 恒 128（`DSA_REQUIRED_CACHE_BLOCK_SIZE`）。
- LIDU slot 15-bit 以内、block-aligned `S ≤ 16256`；支持预算 `(6144,10240,12288)`；block-aligned `C ≤ 16256`；非零 C 的 pool 行须恰有 C 个唯一 slot。

## 7. 契约一致性校验（CI）

独立仓与 vllm-DSA 都运行一份轻量校验：

1. 扫描 C++ schema + `ops_nanovllm` wrapper + `stub`，与本文字段表比对（名称、shape、dtype、别名）。
2. 校验 L1 常量在 `contracts/constants.py`、vllm-DSA `contracts.py`、契约文档三者一致。
3. 校验 8 参 QSFA 唯一化、无 7 参残留。
4. 校验无 `vllm.forward_context` 泄漏到独立仓内核适配层（应通过 `set_timing_context` 注入）。

脚本位置：`nanovllm_dsa_a5/tools/check_contract.py`（stub 模式与真实模式均可运行）。
