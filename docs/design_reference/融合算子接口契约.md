# 融合算子接口契约

文档版本：`2.0.0-draft.1`；修订日期：2026-10-31；代码基线：`fae4597f7`。
本版拆分传统算子与 KVIP V9 两种执行 profile，不能与原稿 1.0.0 直接互换。
此版本是文档修订号，尚未由包导出为 `DSA_CONTRACT_VERSION`，也不是设备 ABI 版本。

本规范中“现有 ABI13”描述已审计实现的行为；“目标要求”定义需要补齐的公开契约。
文档发布不等于实现已达标。符合性与缺口见 [KVIP 实现符合性审计](KVIP实现符合性审计.md)。
[原稿 1.0.0](原稿/融合算子接口契约_v1.0.0.md) 保留传统算子全部签名表作为历史参考。

## 1. 范围和权威边界

### C01 两种执行 profile

| profile | 算子职责 | 框架职责 | 当前实现 |
|---|---|---|---|
| legacy-selection-transfer | LI、LIDU prepare 输出 descriptor；KVAF 单独搬运 | 编排 prepare→BatchGet→metadata→QSFA | `ops_nanovllm.py` 与 `nanovllm_a5_ops` |
| v9-fused-selection | LI、槽位规划、中途预取、最终补取、CQ 汇合和设备结果发布 | 生命周期、恢复、租约、Index 所有权、路由、反馈、metadata/QSFA | `kvip.v9` 与框架 `v9_backend/v9_graph` |

V9 不必实现 BF16 scatter、full dump 或 QSFA 等全部传统函数；这些是独立能力组。
`operators/native_lidu` 仅提供原生 MTP 对照扩展，不表示所有 legacy 算子已经迁入 KVIP。
进程中不能重复注册相同 Torch schema。SFA/tail metadata 的集成仍在框架侧。

公开语义由提供方与消费者共同确认；已发布版本不能由任何一方单独改变。
KVAF runtime/头文件是传输接口权威，消费者契约记录当前所依赖的子集。
机器规范是目标事实源；当前仅部分内容可由 Geometry/tensor_spec 等机器检查，
尚无覆盖整个协议的统一契约包或 `CONTRACT_FUNCS`。

### C02 版本及发现

现有包版本为 `vllm-ascend-kvip 0.1.0`，设备 `ABI_VERSION=13`，
Graph KVAF registration ABI 为 1，Index writer ABI 为 2；各自独立。

目标要求：增加无 torch/NPU 初始化副作用的 `query_capabilities()`，返回至少：

- package version、public contract major/minor、device ABI；
- profile 与 layout 标识、token_bytes/block_tokens、输入头数；
- Q、batch、长度/预算限制、Graph/dummy 能力；
- transport ABI、production/test 标识、SoC/CANN/KVAF 构建兼容信息。

启动先协商，prepare 再检查所选几何和二进制。未知 major、缺必需能力、错误布局或
测试库混入生产须在首次持久写入/通信前拒绝。现有 `load_binding` 仅导入包，
二进制 ABI/大小/offset 检查已存在于 ContractLaunch 初始化阶段，不能说完全没有版本校验。

## 2. 布局与标识

### C03 共享布局

| 量 | ABI13 值 | 含义 |
|---|---|---|
| token_bytes | 656 | attention KV 字节/行：512 FP8 + 64 BF16 RoPE + 4 FP32 scale |
| block_tokens | 128 | 每物理块 token 数 |
| topk | 2048 | 每个 query 的历史选择容量 |
| index_dim / kernel_heads | 128 / 64 | Index key 维度与设备计算头数 |
| model_index_heads | 32 或 64 | pack_query_heads 将 32 头零填充至 64 |
| bitmap_words | 512 int32 | 16384 bit，完整清理与校验 |
| max_queries / selection_capacity | 4 / 8192 | Q4 请求内最大选择总容量 |

目标 LayoutSpec 必须区分 bytes、elements、tokens、blocks，并描述量化格式、scale
位置、字节序与对齐。656 不作为任意模型通用 tensor dim；变更 layout 需要重新协商。
legacy 支持上限 16256、配置预算档 `(6144,10240,12288)` 与 V9 设备容量上限 16384
分别记在 profile；后者并不宣称框架已支持所有整数预算。

### C04 六种标识及寻址

`b` 是 batch 行，`p=pool_rows[b]` 是稳定 pool 行，`t` 是请求逻辑 token，`s` 是
resident 逻辑 slot，`u` 是物理 token 行；packed query 行与这些均不互换。

```text
index_physical(t) = index_table[b,t//128]*128 + t%128
d = (p*num_layers + layer_id)*qcap + t//128
remote_address(t) = address_table[d] + (t%128)*656
u = resident_table[b,s//128]*128 + s%128
resident_address(s) = output_base + u*656
```

地址目录须有效且位于租约注册范围，物理页号不越界。Index 页表与 resident 页表不同；
resident 页表须覆盖预算加 tail 的实际宽度。request identity、pool generation、layer、
mapping epoch 与 batch 顺序分别维护，禁止用 batch 下标作为请求身份。

## 3. V9 请求与输入契约

### C05 Admission 与动态值

现有 ABI13：B 为 1..32，Q 固定 4，同 batch 的 candidate length、logical length、
budget 相同；真实行均为 SPARSE=2；累计 query 长度为 `(b+1)*4`；pool 行唯一且
`0<=p<max_requests<pool_capacity`。候选长度 `1<=C_b<=candidate_capacity`，
`L_b>=C_b`，`2048<=S_b<=resident_capacity`，`S_b+L_b-C_b<=resident_columns*128`。

candidate_capacity 是 256 对齐的 256..262144；resident_capacity 是 256 对齐的
2048..16384；score_stride=candidate_capacity+128；目录、输出池和页表覆盖对应容量。
框架还检查共享 Index 页、pending restore、真实行与 Graph bucket 行数、AIC/AIV 资源。
Q1/Q2/Q3、mixed Q、变长/混合 budget 当前不作为 V9 支持承诺。

目标要求：公开 admission 返回结构化支持/拒绝结果并覆盖 host 可知限制；geometry
和设备值检查继续分层执行。当前 validate_request 只是部分前置检查，返回成功并不
证明上述全部条件满足。拒绝应尽量在 owned Index 重排前完成。

### C06 固定缓冲和访问模式

以下 `B,Q=4,C,S,P,I,R,D` 分别为 batch、queries、候选容量、resident 容量、pool
容量、Index 物理块数、resident 物理块数与目录容量。全部为同设备连续张量。

| 字段 | shape / dtype | 访问与语义 |
|---|---|---|
| query | `[B*4,64,128]` FP8 E4M3FN | 读；model 32 头先 pack |
| weights / query_scale | `[B*4,64]` BF16 / FP32 | 读 |
| key / key_scale | `[I,128,1,128]` FP8 / `[I,128,1]` FP32 | owned 模式可重排/写入；须独占物理页 |
| cumulative_query / candidate_lens / logical_lens | 各 `[B]` int32 | 读；分别为累计 query、候选终点和含 tail 长度 |
| pool_rows / budgets / row_modes | 各 `[B]` int32 | 读；稳定行、有效预算、PAD/DENSE/SPARSE |
| index_table / resident_table | `[B,index_columns]` / `[B,resident_columns]` int32 | 读；图内固定目标地址，可复制新页号 |
| forward / reverse / cursors | `[P,C]` / `[P,S]` / `[P]` int32 | caller-owned in/out；设备成功发布 |
| victims / victim_bitmap | `[B,2048]` / `[B,512]` int32 | 读；有序唯一候选槽及完整 membership |
| address_table / valid_table | `[D]` int64 / uint8 | 读；int64 表达地址位模式 |
| resident_output | `[R,128,656]` uint8 | caller-owned in/out，含 hit、miss、tail |
| profile | `[1]` int32 | 0 正常、1 计时、2 capture dummy |
| index_cache | `[B]` int64 | 读指针表；指向的缓存 payload/metadata 可写 |
| index_dirty | `[B,2]` int32 | 读；脏区间，0<=lo<=hi<=C |
| 输出组 | 见 C08 | 写；不得与读输入或其他写缓冲非法重叠 |

完整字段顺序和工作区形状见 `kvip/v9/contract.py::{TENSOR_FIELDS,WORKSPACE_FIELDS}`，
其设备结构是私有 ABI，不提升为跨版本稳定公共 C ABI。目标要求补字段访问模式表，
覆盖直接输出、间接 Index cache 字节区间及 owned key/scale 的修改。
初始化 validate_buffers 只看 metadata；device preflight 校验动态值，不在 capture 内 D2H。

### C07 V9 的 hot 与 victim 语义

现有 ABI13 的 H0 包含调用前正反映射一致的 resident token，**包括 victim 候选中的
有效 token**。热区阈值使用 `>=` 保护可能进入任一 query TopK 的 hot token；只有
eligible victim 可用于中途预取。最终 logical miss 相对于该 H0 判定并跨四个 query 去重。

legacy prepare 使用“正向表有效且 slot 不在 victim bitmap”判断 hit；两者是不同
profile 的规则，不得以修改文档的方式宣称原本就相同。正确性对照须分别验证选中
token、slot 中 payload 和最终映射；若产品要求 miss/LRU 与 legacy 严格等价，须先
评审统一 H0 定义，再修改实现和 golden case。

## 4. 输出与反馈

### C08 V9 SelectionResult

| 输出 | shape / dtype | 成功语义 |
|---|---|---|
| topk | `[B*4,1,2048]` int32 | 逻辑 token；不足可见候选时允许 -1 padding |
| destination | 同 topk | 每 query 的 resident slot，当前按 miss-first 输出；无效项 -1 |
| miss_counts | `[B+1]` int32 | 请求内 unique logical miss；末项为成功行合计 |
| resident_lengths | `[B]` int32 | `S_b+L_b-C_b` |
| transfers | `[B,4]` int32 | `[预取提交token数, 最终补取提交token数, 两者合计, 丢弃预取数]` |
| status | `[B]` int32 | 见 C09 |
| extra_prefetch_slots | `[B,2048]` int32 | 成功保留但不属最终 TopK 的预取 slot；-1 空洞合法 |
| extra_prefetch_counts | `[B]` int32 | 该行全部非负 extra slot 的数量，**不是紧凑前缀长度** |

topk 与 destination 可能重排，禁止把同下标直接当 token→slot 对。应根据最终映射和
选中 token 集合核对 payload。logical miss 不能用 transfers 替代；transfers 是提交口径，
失败时不表示已完成字节数。“非 TopK”预取可被保留为 extra，并非全部属于丢弃预取。
跨实现不承诺 MTP token→新 slot 的逐位排列相同。

额外预取必须与最终使用 slot 不相交、去重且计数准确。框架 `record_mtp_layer` 接收
两组反馈，`commit_lidu_mixed` 将 extra 作为较旧访问、最终 TopK 作为较新访问。
这些是当前 LRU 的有意扩展；不能只更新最终 TopK 而忽略实际安装的 extra 状态。

### C09 状态与失败

现有状态：OK=0、SKIPPED=1、PENDING=2、INVALID_ARGUMENT=-1、CAPACITY=-2、
DIRECTORY=-3、COMMUNICATION=-4、POISONED=-5。legacy 的 -106/-107/-109 不适用于 V9。

`launch()` 返回只表明 host 提交未立即失败。只有设备完成校验、行状态与框架门控
通过后，才能消费结果。`completion()` 返回非 OK 的已排空业务错误时也可能调用
`mark_completed`：它证明 DMA 生命周期已核验，不证明本行计算成功。

失败时 destination/resident_lengths 不能作为可用业务输出。设备可能已预取覆盖 KV，
Index metadata 也可能已变化；“不发布权威 map”不等于整个物理状态回滚。错误使状态
sticky，未知完成保留资源并 quarantine；不得通过 reset 清错后直接复用。
不得向用户交付某次 Graph guard 生成的安全占位 attention 结果。

## 5. 执行与所有权

### C10 执行顺序

现有默认 launch 为 `init→li→resolve→fetch`；`wait` 为诊断入口，不强制插入正常链。
该阶段数是 ABI13 实现说明，公共行为约束不禁止未来更改 kernel 切分。

1. 框架路由并完成 pending restore，冻结本层 victim/映射；绑定 owned Index。
2. 预构建并初始化固定 buffer、workspace、pointer table 和 queue lease。
3. 首次可能写 resident 或提交 GET 前标记副作用；禁止重叠使用同一工作区/owned cache。
4. init 预检；LI 同时筛选并预取；resolve 规划最终补取、staging 和 Index 维护。
5. fetch 汇合 CQ，核验成功后 PublishResidentState 清旧关系、安装新关系、提交 cursor、
   destination、miss、extra 和 status。
6. eager 图外检查；Graph device guard 后在模型 replay 边界检查；框架记录反馈并消费 QSFA。
7. 完成已核验后释放 eager lease；Graph 注册由 runtime 管理。

### C11 QueueOwnerProtocol

现有 owner 由框架提供，独立包测试提供自己的 owner，均不得依赖 vLLM 内部类。
其协议至少包括 output、device、keepalive、abi_sizes、core_status、build_device_args、
mark_completed(completion_verified=...)、quarantine 与显式 in_flight 生命周期。

KVAF lease 必须核对 output_address、output_bytes、token_bytes=656、block_tokens=128、
jettys_per_core=2、worker_count 及 device entity/queue/status 地址。参数 packer 导出的
args/status/entity/queue 大小与 runtime 必须来自兼容 SDK；仅检查字节数非零还不足以
构成跨版本兼容证明。

目标要求：将 owner 协议公开成可检查的类型及状态机；调用方和包对 acquire、launch、
completion、failure、close 的职责一致，不依靠未写明的调用惯例。
队列在途时输出、descriptor、map、Index、动态库和 workspace 必须持续存活。

### C12 OwnedIndex 生命周期与 epoch

框架证明 key/scale 页独占后才允许重排。缓存归属 `(request identity,pool row,layer)`，
并关联容量、budget、generation 和源存储；grow 只增加候选，write 走对应 bank。
native reader/writer 接手前，须在正确 stream 上恢复逻辑布局；失效/释放不能丢失
仍被异步任务使用的唯一 payload。页面替换需显式失效或可靠迁移，不能仅凭相同地址复用。

mapping epoch=0 进行精确检查；正 epoch 只有在全部外部 map writer 被追踪时可认证
H0 复用；未知 alias/溢出不得重新命中旧认证。它与请求 generation 不同。

### C13 ACL Graph

所有 geometry、device library、输出注册和固定目标 buffer 在 capture 前准备。
capture dummy/profile=2 或全 PAD 不修改持久缓存、不提交真实 GET。
Graph replay 更新固定 pointer table/metadata 的内容，不更换被捕获的目标地址。
同一 bucket/workspace 不并发执行；当前真实 replay 行数须与 bucket 对齐。

Graph owner 要求 fused_graph_abi=1、register_fused_graph_output、begin_fused_graph、
end_fused_graph。device guard 将错误锁存，阻止后续层继续真实操作并安全处理索引；
模型 replay 边界检查失败后隔离。禁止在 capture/replay 内读 CPU count 或编译。
frame 外的完成同步不等同于“实现无同步”；eager 当前还存在每层 acquire/completion 同步。

## 6. 传统 descriptor 和 attention 能力组

### C14 legacy-selection-transfer

传统 LI wrapper 输出逻辑 TopK、不改 resident。ordinary prepare 输出 `[B,1,2048]`
destination、`[B+1]` miss，descriptor 三数组容量各 B*2048；MTP destination 为
`[T,1,2048]`，descriptor 容量各 B*8192，miss 为请求内 unique miss。
有效 descriptor 是全局 `[0,miss_counts[B])` 前缀；不是每行固定跨度前缀。

ordinary 按 miss_slots 前 M 分配、不推进 cursor；MTP 去重并在容量校验成功后推进。
MTP 每 query 的 miss-first 分段长度不等于请求 unique miss，后者可超过 2048。
失败 sentinel 和全部参数/别名参考原稿 §4.5/4.6，并以实际 schema 联检。

KVAF batch_get 接收 address_table、valid_table、indices、offsets、total_miss_count、
output_indices、output_rows、stream、synchronize_batch_get 九个位置参数。
count 是 int32[1] 设备标量；output_rows 为 `[physical_tokens,656]` 字节视图。
caller 负责注册、跨 rank 及 stream 完成依赖；V9 成功后不能再执行该路径重复取数。

### C15 metadata 与 QSFA

build_c8_attention_metadata 只写 attention_slots，resident_seq_lengths 只读返回；
每轮完整覆写，sparse 前缀拼 `[S_b,S_b+tail)`，cache_tokens=0 按有效 dense 长度处理。
QSFA C8 保持现有八参接口和选中长度，不要求其移入 V9 独立包。
既有 C8 LIDU 读 forward_context/非 capture 同步属于兼容路径，不描述为已改显式参数。
目标注入使用调用或 session 的不可变上下文；不引入进程级可变 timing setter。

## 7. 测试、性能与版本演进

### C16 分级验收

1. host oracle：选择集合、payload、映射、unique miss、extra、tail、换序和源改写。
2. host transport：延迟完成、异常和资源存活；不以全量 sentinel 填充代替真实 payload。
3. NPU memory：实际 kernel 和本地测试源复制；与生产二进制强隔离，不声称网络性能。
4. real KVAF：真实 lease/SQ/CQ、完成可见性、失败恢复和跨 rank。
5. framework：eager/Graph、worker 生命周期、fallback、QSFA 和模型端到端。

每级报告环境、源/SDK/库 fingerprint 与证据；CPU 模型不代表执行了设备 kernel。
FakeNpuRuntime 若用于传统 adapter 测试，应匹配实际签名、校验全局有效前缀并保持
未写 hit/tail；D2H 校验只允许 CPU 或图外测试。V9 还需 owner/queue 专属桩。

### C17 性能约束

版本/能力在启动检查，几何/固定 buffer 在 prepare 检查，动态值在设备预检。
准备后的 enqueue 不做动态构建、host count 读取或全局后端查找。目标复用缓冲；
不能由此声称当前 eager 无分配、当前 32 头 packing 无拷贝或派发零成本。
分别测量 host dispatch、setup、selection、完成同步与模型 TPOT，Graph 结果包含真实
边界开销；重叠阶段时间不得直接相加。量化格式变更与同步优化单独验收。

### C18 演进规则

公开语义、必需参数、布局、别名、错误或同步保证的破坏性变化升级 MAJOR；
向后兼容的可选能力及 keyword-only 扩展可升级 MINOR，但 Torch/C ABI 独立验收；
不改变行为保证的澄清/修复升级 PATCH。缺失能力按 profile 拒绝，不强行兼容。
当前 ABI13 裸结构没有 size/version extension header；后续稳定公共 C ABI 需另设计，
不得仅在结构末尾加字段后宣称 minor 兼容。
