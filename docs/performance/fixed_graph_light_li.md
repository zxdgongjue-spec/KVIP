# 固定图中的精简 LI 模式

目标是同一层组在不同 decode 轮次复用同一张图，按需求关闭投机工作。
它不是按层号选择串行/融合，也不依赖条件子图或 CPU 逐层同步。

## 本次实现的边界

新增默认关闭的构建选项 `low_miss_skip`，依赖 `adaptive_admission`。
沿用现有固定地址 `int32[B,4]` admission 控制表和上下文 ABI。
只有所有有效格式的控制行都满足 `total=0`，才进入精简模式；任意行
具有正额度时，整批保留原融合流程。控制表只能在上次调用结束后、
本次图执行前更新。一次调用内不能改变模式。

**零额度是调用者选择的策略，不是已经知道本轮没有 miss。** 即使
本轮 miss 突然升高，最终精确 Get 仍必须取回全部缺失 KV。
本次没有把自动 miss 预测接入服务；先测出精简模式的实际成本，
才能判断预测和切换是否有价值。

图节点顺序、输入输出地址、Index 布局、CPU `miss_slots` 及最终
缓存更新规则保持一致。普通 LI 模式仍为 init → LI → 精确收尾。
sequence-split 模式保留既有 LI 子阶段节点；早阈值节点在精简模式
返回，但其节点下发成本仍包含在完整计时中。

| 工作 | 精简模式 | 原融合模式 |
|---|---|---|
| 本轮必要状态初始化 | 保留 | 保留 |
| resident＋近期的提前计分和初始阈值 | 不执行 | 保留 |
| 全历史本轮分数及最终 Top2048 | 完整执行 | 完整执行 |
| 提前计分时的窗口分类、进度和预取 | 不执行 | 保留 |
| 计算核与向量核的正常算分流水 | 保留 | 保留 |
| 专供预取使用的核间等待 | 成对跳过 | 保留 |
| 最终 TopK 的 hit/miss、Q4 去重及槽位分配 | 保留 | 保留 |
| CPU 生成的回收候选、ABC 和 candidate-hot 规则 | 保留 | 保留 |
| Get、Index 更新、输出和完成确认 | 保留 | 保留 |

复用 `ProcessVec1(scoreOnly=true)`，仅删除投机分类，不删除计算
所需的 AIC/AIV ping-pong。低模式仍完整扫描近期区间；不能跳过
早期计分后又沿用“近期已经算过”的条件。依赖早阈值的最终 TopK
剪枝关闭，防止读到上一轮阈值。普通 LI 的预取 flag 8 生产/等待
两端一起跳过，最终分类也不等待未执行的预取窗口。

## 为什么第一步保留 init 和精确收尾

它们维护下一轮继续使用的权威状态。把节点变成空操作只节省工作，
并不会让后继读取旧状态变得安全。本次保留其原有契约，以便单独
测出早阈值和窗口协议的成本。后续若该路径仍慢于强串行，应根据
实测缩减初始化和无预取收尾，而不是仅调预测阈值。

当前精简模式使用本项目 LI 实现，不能称为原生串行 LI，也不能
预先承诺它比原生串行快。运行时分支仍可能改变编译寄存器分配；
因此需要同时测新二进制的高模式是否损伤现有融合性能。

## 设备自动选择的后续接入设计

精确 miss 数直到最终 TopK 后才知道。调用开始时选择路径必须用
因果预测，不能把本轮正确性检查读回的计数冒充在线输入。

计划在现有 init 的指定 block 中读取上一成功轮反馈，结合本轮
Q 数、历史长度和 token 字节宽度估计完整成本；模式由 kernel
边界发布给后续 LI。首版其余 init block 不依赖尚未发布的模式，
避免新增跨 block 屏障。

反馈以 `(层组, owner, owner_epoch)` 标识请求生命周期，不以
层号固定高低，也不以 captured BS 作为请求身份。共同完成点
记录去重后的必要 Get 数、Q 数及 step_id；不把无效预取记成需求。
capture、预热和重复 step 不更新真实历史。信息不足时先走精简
模式；低估时精确收尾仍处理所有 miss，只损失提前搬运的机会。

选择依据应是同设备、相同 shape 和 token 宽度下两条完整链的
实测交叉点，并留出误差余量；固定 3% miss 阈值不能代表所有负载。
`miss_slots` 是 CPU 准备的回收候选，固定长度不等于真实 miss 数。
这部分接入尚未实施，本轮不报告自动策略的性能收益。

## 最小验证

复用五组真实 Q/Index、合成 KV 输入，保持 BS16、Q4、656B、NPU4。

1. 强串行仍为 workers32、post128、inflight2048、2 jettys。
2. `quota-zero`：原融合设零额度，仍保留早阈值/窗口协议。
3. `light-low`：新二进制零额度，实际跳过上述工作。
4. `light-high`：同一新二进制恢复正常额度。
5. 首尾重复对照区分漂移；比较 mean 和 p50，不只取较好一个。
6. 单次捕图后按 0→512→0 原位更新 controls；检查地址不变、精简
   回放预取为零、全部分数/有序 TopK/KV/Index 正确。

交替模式检查每次仍恢复同一快照，因此证明的是固定图切换和
轮内状态复位，不代替连续服务中无恢复的缓存生命周期验证。
恢复快照和验证排除在计时外；图内 init、LI、Get、Index 和输出
全部计时。未计算的早阈值明确标记为 `not_computed`，最终结果
校验不放宽。控制表 CPU 更新和 H2D 不计入设备图耗时，自动
策略上线后其设备选择及反馈必须计入。
